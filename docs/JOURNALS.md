# 저널 발행목록과 방법론 색인

정치학 종합 9종, 정치방법론 3종, 비교정치·지역연구 11종, 국제관계·안보 10종, 선거·정치행태·여론 5종, 정치경제 3종, 공공정책·행정 7종, 정치이론 3종을 선정했다. 인접 분야를 포함하며 배열 순서는 분야별이다. 저널 ID는 영구 식별자다. 명칭·약칭·분야·공식 사이트를 설정에서 수정할 수 있다. 인쇄·온라인 ISSN은 Elsevier Scopus 2026년 7월 출처 목록에서 정식 명칭으로 대조했다. 자료에 누락된 매체의 근거는 해당 저널에 별도로 기록했다. [저널 설정](../catalog/journals.json) · [Scopus 출처](https://www.elsevier.com/products/scopus/content)

## 수집 범위와 날짜

첫 실행은 서울 날짜에서 달력상 5년을 거슬러 올라간 날부터 실행일까지 포함한다. 첫날과 첫 실행일을 고정하고 이후에는 그 첫날부터 매번 다시 조회한다. 초록 유무·인용수·방법에 따른 수집 조건은 없다. Crossref의 저널 발행물에는 연구논문, 연구노트, 이론·방법론 논문, 리뷰, 서평, 정정 등이 함께 들어온다. 출판사가 종류를 표시하지 않으면 세부 유형을 미확인으로 둔다.

Crossref에 등록된 인쇄·온라인 ISSN을 OR로 결합해 발행일 필터와 커서를 사용한다. 마지막 짧은 페이지 또는 빈 페이지, 수신 건수와 보고 건수가 일치하는지 확인한다. 커서 값이 유지돼도 실제 결과가 바뀔 수 있으므로 페이지 내용으로 반복을 검출한다. OpenAlex는 같은 저널의 주 게재처와 발행 기간으로 독립 조회한다. 연도별 DOI 교집합과 차집합을 기록한다. 등록 시차와 두 출처의 발행일 정의가 다를 수 있다. DOI 차집합은 추가 확인 대상이다. 권호 목차와의 개별 연결 수, 전체 출판사 대조 여부, API 페이지 수신 완료 여부를 각각 표시한다. [Crossref API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/) · [OpenAlex](https://developers.openalex.org/)

논문의 온라인 선출판일, 권호 발행일, 일반 발행일을 보관한다. 알려진 발행일 중 최초를 연도 집계에 사용하며 같은 연·월의 더 정밀한 값이 있으면 그 값을 쓴다. 연·월만 있는 경우 화면에 정밀도를 표시한다. API가 기간 안에 반환한 저정밀 날짜는 확인 가능한 범위가 수집 창과 겹칠 때 포함한다. 보완 자료의 연도만으로 시작 연도의 11월 19일 전후를 가를 수 없는 기록은 보류했다. 저장소의 등록일, Crossref 색인 시각, PoliHub 최초 발견일은 별도 항목이다.

정규화한 DOI, 제공자의 영구 논문 ID, 저널·제목·저자·발행연도·권호를 순서대로 대조한다. 발행 날짜 정밀도와 누락 필드는 보완할 수 있다. 상충하는 DOI와 모호한 서지 정보는 통합을 보류한다. 재현 자료·코드·외부 데이터는 논문의 관련 자료로 저장한다. 패키지 DOI나 저자 키워드가 아닌 출처의 주제 분류를 논문 DOI·저자 키워드에 대입하지 않는다.

## 초기 보완 자료

첫 로컬 수집에서 Crossref와 OpenAlex API는 환경 프록시의 403 응답을 받았다. 아래의 공개 서지자료와 확인한 공식 자료를 사용했다. 저널·연도별 발행목록의 완결성을 주장할 수 있는 범위는 화면의 출처별 기록에서 확인한다.

- Göttingen SUB의 HOAD에서 선정 ISSN에 속하는 DOI와 Crossref 최초 발행연도(`cr_year`)를 대조했다. 하이브리드 오픈액세스 중심 자료이므로 구독 논문과 전면 공개 저널이 과소대표된다. 제목을 확인하지 못한 DOI도 유지한다. [사용한 R 데이터](https://github.com/subugoe/hoaddata/blob/b3e5e0bc0311a41603d094aa344dce5bc53e8c96/data/cc_articles.rda)
- Paper Picnic의 주간 Crossref 서지를 저널과 DOI로 연결해 제목·저자·초록 유무·방법 근거를 보완했다. 주간 게시일만 있는 DOI는 그 날짜로 기간을 판정하지 않았다. [현행 자료](https://github.com/sumtxt/picnic/tree/e8cb5b18d7853f3675537aeaadbc1314c7cbccf6) · [이전 수집 자료](https://github.com/sumtxt/picnic/tree/d14d91dcefa784926fa744808df56caf13612920)
- Journal of Public Economics는 권호 목차 기반 서지와 그 출판사 링크를 연결했다. Comparative Politics는 CUNY가 게시한 권호별 논문 제목·저자·연월을 대조했다. 일부 권호만 포함하며 표제 연도가 충돌한 권호는 보류했다. [JPubE 권호 자료](https://github.com/kochiuyu/econ-journal-authors/tree/c54c997888859067223103b659f4ee98d059b71b/releases/articles_toc_2010_2025) · [Comparative Politics 공식 사이트](https://jcp.gc.cuny.edu/)
- Hall의 AI 연구 서지에서 확인된 논문 DOI와 발행연도를 사용했다. Harvard Dataverse의 관련 논문 서지와 패키지는 공개 스냅샷에서 저널·고유 제목 또는 명시적인 논문 DOI를 대조했다. 패키지 설명에서 가져온 근거와 논문 초록을 구분했다. [Hall 서지](https://github.com/andybhall/ai-in-political-science/blob/5db77ca6fa63c520611a1d0d0d0113975ca7b6dc/ai_papers.csv) · [Dataverse 메타데이터](https://github.com/jsakowuah/polisci-replication/blob/21ae1bd811e5b09efbc77673b894b8218c1a40a7/data/raw/dataverse_datasets.csv)

## 방법 분류와 분모

분류표는 각 방법의 원어·별칭과 한 단계 위의 개념을 담는다. 논문에서 관찰한 구체적 표현, 역할, 근거 위치·링크를 별도로 보관한다. 본문·재현 코드 직접 확인, 초록·공식 재현자료 설명에 적용 명시, 방법명 단서, 미확인의 네 수준을 사용한다. 자동 처리는 저자가 해당 방법을 사용했다고 직접 기술한 제한된 문장 패턴에 적용한다. 맥락이 불분명하거나 비교·부정·선행연구 패턴이 있으면 단서로 남긴다. 직접 확인은 사람이 근거를 대조해 추가한다. 다국어·간접 표현과 전문 전체를 포괄하는 자동 판독은 미확인 영역이다. [분류표](../catalog/methods.json) · [직접 대조한 논문](../catalog/reviewed-papers.json)

적용 확인은 직접 확인과 적용 명시를 포함한다. 같은 논문에 연결된 세부 방법들이 한 상위 분류에 속하면 가장 높은 근거 수준 한 건만 센다. 서로 다른 상위 분류에는 각각 한 번 기여한다. 서평·정정·철회·편집자료 등 식별된 비연구물은 발행목록에서 열람할 수 있고 방법 분모에서는 제외한다. 리뷰 논문은 포함한다. 연도별 그래프에서 근거 확보율은 해당 논문 분모 중 초록 또는 명시적 적용 근거를 확보한 비율이다. 주간 자료의 초록은 근거 생성에만 사용했고 전문이나 설문 원본을 복제하지 않았다.

## 월별 실행과 장애

`python -m polihub.journals`는 로컬과 Actions에서 같은 명령이다. 서울 매월 1일 09:20(UTC 00:20)에 예약되며 GitHub Actions의 수동 실행도 같은 고정 구간을 재조회한다. 새 버전 번호가 기본 브랜치에 반영될 때 첫 배포도 시작한다. 원한다면 저장소 변수 `CROSSREF_MAILTO`와 비밀 값 `OPENALEX_API_KEY`에 공식 API의 연락처·키를 설정할 수 있다. 제공자 인증 요구나 거절은 출처별 오류로 기록한다.

실행 잠금 안에서 기존 색인을 검증하고, 새 스냅샷을 같은 디렉터리에서 원자적으로 교체한다. 실패한 출처의 이전 자료와 직접 확인 근거는 보존된다. 종료 코드 2는 Crossref 일부 또는 전체 미완료다. 워크플로는 실행 요약·부분 결과를 보존한다. 저장소 반영은 fast-forward 푸시를 사용한다. 기본 브랜치가 거절하면 실행별 브랜치와 PR로 보낸다. GitHub가 봇 PR 발행을 막은 경우 실행 로그의 브랜치를 확인할 수 있다. 기본 브랜치 반영 후에는 실행별 Release에 버전 이름을 가진 HTML을 첨부하고 다시 내려받아 원본과 대조한다.
